# Selective LR compensation (Krea 2, Muon)

Off by default. On Krea 2, choose Global replay, enable Selective block check, select built-in Muon (match_rms_adamw), AdamW, AdamW8bit or PagedAdamW8bit, and enable Selective LR compensation. The policy, warmup and eight-update probes are unmodified. At each optimizer update multiply only the post-orthogonalization learning term by min(1.5,sqrt(28/active_count)); no extra model forwards, matrix decomposition, scheduler changes, or LR group changes. All-active steps use 1.0; skipped factors do not receive decay or momentum updates. The active gradient mask is checked before stepping. Actual nominal probe-selected multipliers appear in the log. Normal training is unchanged. The AdamW-family expansion is under compatibility testing on test/selective-optimizer-support only; the provisional 1.8x AdamW-reference conversion is NOT included.

Based on research branch test/selective-movement-forks, experiment 7G.1, two seeds, 13 train images, two held-out images, 65 updates per seed, rank/alpha 32/32, Muon native LR .00045, native INT8 Krea2. Mean EMA loss full .180477607, existing .180544726, compensated existing .180315870. Raw loss improved on both seeds; EMA improved on seed 42 but slightly regressed on seed 43. Mean reported step time fell only 1.21% vs full; not a significant throughput claim. See research branch final report for full limitations. No global replay harness or research solvers are included in this port.

Resume: same compensation setting is required; older states without a flag are uncompensated. The existing selective resume restores scores and activity but reanchors displacement at resume, so bitwise equivalence is not guaranteed. CPU regression tests were added for the learning term and skipped state; execution has not yet been confirmed. Full Windows/CUDA training, UI dependency, pause/Save & stop/resume, interactions with Adaptive LR/per-image LR, and generalization across datasets have not yet been verified for this production port. The feature is presented without an experimental label and remains opt-in, preserving established presets. These outstanding production compatibility checks are still required; no further exploratory arms are required.

## AdamW-family compatibility branch

Built-in Muon retains its direct learning-term multiplier. Native AdamW, AdamW8bit and PagedAdamW8bit keep their native step implementations. On a compensated update, temporarily set group lr to lr*c and weight_decay to wd/c, preserving lr*wd in real arithmetic. Restore the original values in finally before the scheduler, EMA, state save or next update. Full probes call the native optimizer with no changes. No extra parameter copies, optimizer state, quantization/dequantization, forwards or geometry. Native fused/foreach paths are retained. Floating-point rounding and native backend ordering may differ slightly; do not assert bitwise equality of the compensated weights. No silent optimizer fallback. 8-bit per-parameter LR/decay overrides, update-norm limits and skip_zeros are rejected for compensated steps; first full update initializes BNB. Resume requires identical optimizer and compensation setting. Existing Muon-only saved state defaults to optimizer name muon.

Tests: checks/test_selective_optimizer_support.py covers scalar/foreach CPU AdamW and optional CUDA fused AdamW, 8-bit and paged variants, including nonzero decay, multiple parameter groups, moment/state preservation, skipped updates, reactivation, native probe, scheduler visibility, serialized state, and error restoration. Run in the project's environment; CUDA cases are skipped without CUDA. This proves implementation mechanics, not training quality or universal optimizer equivalence. Additional optimizers remain unsupported until their semantics are assessed. No production WIP changes on this branch.
