# Selective movement forks — foundation (6B/6C)

Isolated from Experiment 5C. This is an opt-in research library, not a new Test Mode queue.

The native Muon proposal observer records the actual decayed factors, native update tensors and adjusted LR, after the ordinary momentum/orthogonalization calculation and before the native add. No change to default optimizer mathematics. Use after full-block backward and clipping, before EMA, scheduler or selector advancement. Standard LoRA only; exactly the paired factors must be in the optimizer, all with gradients. Do not use during ordinary training or concurrent evaluation.

`capture(network_pairs(net), optimizer, generators=(training_generator,))` is an in-memory transactional context. It invokes the native optimizer once, checks bitwise replay at 1x, exposes the common updated optimizer buffers, and restores raw weights, incoming optimizer state, Python/NumPy/PyTorch RNG and explicit generators on exit. It does not save a disk checkpoint, or snapshot arbitrary model buffers, scheduler, EMA or selector. Do not mutate those during a fork. All evaluator calls must be forward-only and reset their own RNG/inputs. No multi-step resume support yet.

`match(fork, allocations, minimum=..., atol=..., rtol=...)` constructs finite fixed-decay quartics with compact FP64 QR cores, truncates the continuous search at the first decreasing interval, matches the largest shared reachable norm without scaling above 1, and measures committed endpoint displacement at the original parameter dtype/device. Bounded rounding repair uses only movement. Initially decreasing/degenerate/unreachable curves and out-of-tolerance realized pairs are rejected and must remain in the denominator. The actual per-block squared displacement is reported. Identical static/adaptive choices must remain in the comparison. Allocation dictionaries must be locked before outcomes; include the timing control in the same match or rematch all arms. A 0 multiplier in this library keeps native decay and momentum and is NOT true suspension.

CPU synthetic checks: `python -m pytest checks/test_replay_forks.py -q`. Native parity, compact vs dense endpoint norms, nonmonotonic curves, low-precision rounding, RNG and momentum rollback, exception rollback. These are not real diffusion results. Full Krea 2 GPU parity, actual peak memory, runtime, matching failure rate, disk resume parity and independent forward-only evaluation integration are outstanding. CPU snapshots use multiple factor-sized buffers, and candidate replay transfers native directions back to the device; measure cost on the 12 GB card before queueing. No change to the 5C recipe, production branches or Matrix Geometry.
