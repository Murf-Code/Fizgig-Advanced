# 5D-short: three-arm reduced-dataset retest

This is a new small-dataset exploratory comparison, not an independent seed replication. Preserve the 5C logs. Select a separate folder containing roughly 16 representative image/caption pairs, including explicit anthro tags where appropriate. Do not change the folder during the queue. The trainer requires 8–20 training batches after automatic holdout and a complete holdout cache; typically 14–15 training images gives 70–75 updates over five epochs.

The queue runs unrestricted 0.00030, unrestricted 0.00045, and Adaptive Gradient 0.00045. All other optimizer, rank, seed, deterministic precision, preview prompts and validation settings retain 5C controls. Full probes remain every eight optimizer updates. This changes the number of updates and held-out images; do not compare absolute scores with 5B/5C as if the dataset were unchanged. No schedule or selector change; only the three selected arms.

New per-comparison cache namespace forces fresh text and image encoding on the first arm, reused within that comparison. This avoids stale cache reuse, but does not prove the user actually edited captions. Save normal final EMA exports and final FP32 raw/EMA research factors only; no resume states or intermediate checkpoint exports. Keep validation and preview images every epoch, including baseline previews. At least 8 GiB free required at queue launch, 2 GiB before final research export per run. No automatic deletion. Report retains actual steps/epoch, holdout names and per-step masks, fingerprints, LR, probe telemetry, epoch raw/EMA validation, samples, and final completion marker.

Expected checkpoint storage approximately 3.6 GB decimal for three arms (107.3M factors × 4 bytes × 2 plus two BF16 final copies per arm), plus cache, previews and logs. Actual output dtype and disk use may differ. No historical checkpoint geometry can be recovered from logs alone if tensors were deleted. No changes to movement-fork branch.
