# Experiment 5A — reproducibility
Use the existing Test Mode queue on the research branch with the original dataset (29 training / 3 holdout). Five independent seed-42 adaptive-gradient runs at 0.00045, rank 32, Muon, INT8; all plan five epochs but finish normally at epoch two (58 optimizer updates).
A1/A2 default kernels, A3/A4 strict PyTorch deterministic algorithms, A5 same strict settings plus probe factor telemetry and EMA validation. All arms log exact raw-factor SHA-256 at step 0 and every update, plus actual gradient-bearing masks and next masks. Hashing is deliberate diagnostic overhead; times are not clean production throughput. Strict mode can fail or exceed VRAM; do not silently fall back. Kernel flags/policy are logged, not a profiler-confirmed dispatch trace.
Raw validation is unchanged; A5 also validates EMA. FP32 raw and EMA snapshots are retained locally for epochs 1 and 2 (roughly 8.6 GB across the queue, excluding normal checkpoints/states). The report ZIP excludes weights. Do not resume these partial diagnostic runs as if they were completed five-epoch LoRAs. Compare exact hashes before interpreting loss differences. A1/A2 measure only one pair of normal runs, not a population noise floor. A3/A4 must match through step 58 before using A5 as a neutrality check. If strict mode fails, collect the failed log; no automatic substitution. Production defaults and selection algorithm are unchanged.
