# Round 5: asynchronous checkpoint input offload

Implementation at 1e136d23e91ecf383b5df554aa5ad41747e32749 on research/polora-kernel-efficiency. Research-only, no change to default sync or production settings. Rank-aware NS deferred per user. Previous Round 4 A/A uncertainty remains open.

## Architecture
Use existing nonreentrant checkpoint saved-tensor boundary and selection, immutable contiguous full-storage checkpoint activations only. AsyncHostBudget owns one D2H stream per CUDA device. A pinned CPU tensor receives nonblocking copy after producer-stream wait; record_stream protects source allocation reuse. Record readiness event, then return host lease. Demand H2D restoration waits on readiness in the consuming stream and copies nonblocking on that stream, before recompute. No speculative backward prefetch or changes to weight-stream scheduling. Completion events retain pinned payload until all restores and D2H finish; weakref finalizer merely retires the payload, no CUDA calls there. Reap completed retired payloads before admission. Drain retired events at update boundary; live graph leases never released by drain. Host cap counts active and retired payloads; not OS pin/caching allocator overhead or total RAM. Pinned allocation failure aborts arm, no silent fallback. Existing immutable-input/version check limitations persist. One device, eager, standard LoRA, no retained graph, no compile. D2H overlap may delay GPU allocator reclamation and contend with weight H2D. No claim of backward peak reduction or faster runtime.
